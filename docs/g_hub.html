Status, Add, Reset, and Commit

After changing the folder, we need to check the status of the folder, to add or reset the folder.

git status
git add --all # alternative is git add -A
# git add . seems to do the same. However, it stages the file someone is currently at. It doesn't stage files of the parent folders.

git reset # This unstaged or unadded all the files 
git reset HEAD~ # This takes back to the previous status before the last commit
git reset --hard # Normal reset only unstage the files, but it doesn't bring back the deleted files. To bring back the deleted file --hard is needed. 

git add --all
git commit -m "adding a new folder"

# If this is the first commit, then you may need to do
git config --global user.email "your_email"
git config --global user.name "your_name"

Git Log

Git log is the most important command for knowing different versions.

# To know the history
git log

# To know only the summary about the history
git log --oneline

When we talk about different versions and version control, branching comes. Branching is another important idea in git.

# To know about existing branches
git branch

# To create a new branch
git branch developement #developement is the given name

When a git branch is created, it exactly copies the current branch at the time of creation. After the creation, we need to switch to that created branch if we want to make changes to that version.

# entering into the branch
git checkout developement

# Now you can add a file to that folder
# Then stage it using git add command
git add .
# Finally, commit the changes
git commit -m 'five.txt file added'

# Now if you switch to the main brach,
# surprisingly, you won't see the five.txt
git checkout main
ls
# not any five.txt file shown

Suppose one person is working in the main branch. Another person copies that and does additional updates to the folder. By the meantime, new changes have been made in the main branch. Now, both folders have different updates. Unless both folders have changed the same named files, it is better to merge the main branch to the new branch. And finally, new branch should be merged to the main one.

# changes have been made in the second branch developement
# Now, go to main branch and make some changes
git checkout main

# after some changes
git add .
git commit -m 'one.txt has been changed'

git checkout developement
git merge main -m "merging main into the developement branch"

git checkout main
git merge developement -m "merging developement to main"

If changes have been happened in the same file of different branches and we want to merge those two branches, then auto merge will fail. Then you need to open the conflicting file manually and select the version you want. After having the desired modification, you need to add and commit the new changes as per usual rules.

Using commit ids as branch name creates ample opportunities in the era of version control.

# bring the log history
git log --oneline

# going back to past

Remote repository or GitHub

It is surprising that if you download the git repository from github and work on the folder, the system remembers the remote github repository. Therefore the following command is enough to upload the adjustment made in the local repository.

git push origin main

# or if you want to create a new branch in github 
git push origin developement

# Similarly git fetch
git fetch
git merge

# git pull in the combination of git ferch and git merge
git pull # git pull = git fetch + git merge
